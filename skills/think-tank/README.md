# Think Tank - 项目智囊团

项目智囊团是一个多角色协作评审系统，通过智能调度六大专家角色，为项目决策提供全方位支持。

## 特性

- **智能路由**：根据任务类型自动选择合适的专家角色
- **并行评审**：独立专家并行工作，提高效率
- **冲突协调**：自动识别专家意见冲突，辅助用户决策
- **项目背景**：自动生成和维护项目背景文档
- **需求确认**：评审前与用户确认需求和角色选择

## 专家角色

| 角色 | 职责 | 适用场景 |
|------|------|----------|
| 商业/财务架构师 | 盈利模型、资金流、UE模型 | 定价策略、商业模式、成本分析 |
| 市场/用户调研专家 | 需求验证、竞品分析、用户接受度 | 新产品、功能优先级、市场定位 |
| 运营/供应链架构师 | 流程设计、运力规划、地推策略 | 运营优化、流程改进、资源分配 |
| 法务/合规顾问 | 法律风险、合规要求、隐私保护 | 数据处理、用户协议、合规审查 |
| 产品设计总监 | 业务抽象、MVP定义、功能规划 | 产品设计、功能规划、交互流程 |
| 技术架构师 | 技术选型、架构设计、成本评估 | 技术实现、架构决策、性能优化 |

## 安装

```bash
python3 install.py --module think-tank
```

## 快速开始

```bash
/think-tank <你的项目需求或问题>
```

## 使用示例

### 新产品设计

```bash
/think-tank 我想做一个小城市生鲜电商平台，主要卖非标品（活鱼、蔬菜）
```

智囊团会：
1. 确认需求理解
2. 建议参与角色（全员）
3. 并行评审：市场调研 + 技术评估 + 法务合规
4. 串行评审：商业建模 → 运营规划 → 产品设计
5. 识别冲突（如定价策略、配送模式）
6. 输出综合评审报告

### 运营问题

```bash
/think-tank 我们的物流和人力成本太高，需要优化方案
```

智囊团会：
1. 确认成本类型
2. 调用运营架构师 + 商业架构师
3. 并行分析成本结构和优化方案
4. 输出优化建议和 ROI 预测

### 技术选型

```bash
/think-tank 我们需要选择一个消息队列方案，在 RabbitMQ 和 Kafka 之间纠结
```

智囊团会：
1. 调用技术架构师 + 商业架构师
2. 技术评估：性能、可靠性、学习成本
3. 商业评估：成本、运维投入
4. 输出选型建议

## 工作流程

```
用户需求
    ↓
需求确认（AskUserQuestion）
    ↓
角色选择（用户可调整）
    ↓
并行评审（独立角色）
    ↓
串行评审（依赖角色）
    ↓
冲突识别（如有）
    ↓
用户决策（如有冲突）
    ↓
综合报告
```

## 项目背景

首次使用时，智囊团会自动生成 `.think-tank/project-context.md` 文件，包含：
- 项目概述
- 技术栈
- 业务模式
- 目标用户
- 当前状态
- 关键约束

后续评审会自动读取这个背景文档，确保所有专家了解项目全貌。

## 依赖

- codeagent-wrapper（支持 `--agent` 参数）
- 至少一个后端 CLI（claude/codex/gemini/opencode）

## 与 omo 的区别

| 维度 | omo | think-tank |
|------|-----|------------|
| 定位 | 代码实现编排 | 商业决策支持 |
| 角色 | 技术专家（explore/oracle/develop） | 跨职能专家（商业/市场/运营/法务/产品/技术） |
| 输出 | 代码变更 | 决策建议和评审报告 |
| 冲突处理 | 技术方案选择 | 跨职能冲突协调 |
| 适用场景 | 开发任务 | 项目规划、战略决策 |

## 最佳实践

1. **明确需求**：描述清楚你的问题或需求，包含背景信息
2. **选择角色**：如果你知道只需要特定专家，可以在确认时调整
3. **提供约束**：告知时间、预算、资源等约束条件
4. **决策冲突**：当专家意见冲突时，根据你的优先级做决策
5. **更新背景**：项目变化时，手动更新 `.think-tank/project-context.md`

## 示例场景

### 适合使用智囊团的场景

- ✅ 新产品/功能设计
- ✅ 商业模式调整
- ✅ 重大技术选型
- ✅ 运营策略优化
- ✅ 合规风险评估
- ✅ 定价策略制定

### 不适合使用智囊团的场景

- ❌ 简单的代码实现（用 /omo 或 /code）
- ❌ Bug 修复（用 /omo）
- ❌ 文档编写（用 /docs）
- ❌ 单一技术问题（直接问技术问题）
