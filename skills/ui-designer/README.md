# UI Designer - UI 设计师

UI 设计师是执行层角色，负责基于产品需求文档（PRD）产出 UI 设计方案和设计规范。

## 特性

- **规范化**：建立统一的设计规范（配色、字体、间距、组件）
- **一致性**：所有设计遵循设计规范，确保视觉一致性
- **可实现**：设计方案考虑技术可行性，便于开发实现
- **可追溯**：所有设计保存在 `.think-tank/design/` 目录

## 安装

```bash
python3 install.py --module ui-designer
```

## 快速开始

```bash
/ui-designer 基于生鲜电商平台的 PRD，设计 UI
```

## 工作流程

```
PRD（产品需求文档）
    ↓
ui-designer（设计 UI）
    ↓
设计评审
    ↓
设计方案正式生效
    ↓
开发团队实现
```

## 设计产出内容

1. **设计概览**：整体设计思路和风格
2. **页面设计**：每个页面的详细设计（布局、元素、尺寸）
3. **组件库**：可复用的 UI 组件（按钮、输入框、卡片等）
4. **交互规范**：交互细节和动效说明
5. **设计标注**：尺寸、间距、颜色标注

## 使用示例

### 示例 1：基于 PRD 设计 UI

```bash
/ui-designer 基于生鲜电商平台的 PRD，设计 UI
```

UI 设计师会：
1. 读取 PRD 文档
2. 理解功能和交互流程
3. 设计每个页面的 UI
4. 产出设计文档
5. 提交设计评审

### 示例 2：设计特定页面

```bash
/ui-designer 设计商品详情页的 UI
```

UI 设计师会：
1. 理解商品详情页的功能
2. 设计页面布局和元素
3. 产出设计方案

## 设计规范

首次使用时，UI 设计师会询问用户的设计偏好：
1. **品牌色偏好**：蓝色 / 绿色 / 红色 / 其他
2. **设计风格**：简约 / 商务 / 活泼 / 其他
3. **参考案例**：类似某个 App（可选）

根据用户反馈，创建设计规范文档（`.think-tank/design-system.md`），包含：
- 配色方案（主色、辅助色、中性色）
- 字体规范（字体家族、字号、字重）
- 间距规范（基础间距、常用间距、页面边距）
- 组件规范（按钮、输入框、卡片等）
- 交互规范（页面切换、按钮点击、加载状态、错误提示）

后续所有设计都遵循此规范，确保视觉一致性。

## 设计产出示例

### 页面设计

```markdown
## 页面：首页

### 设计思路
简约风格，突出商品展示，方便用户快速浏览和购买。

### 页面结构
- 顶部导航栏：Logo + 搜索框 + 用户头像
- 分类导航：蔬菜、肉类、水产
- 推荐商品：商品卡片列表
- 底部导航栏：首页、分类、购物车、我的

### 设计元素
- 顶部导航栏：高度 56px，背景色 #ffffff
- 商品卡片：宽度 (屏幕宽度 - 48px) / 2，圆角 8px
- 价格：字号 16px，颜色 #f5222d，粗体
```

### 组件设计

```markdown
## 组件：商品卡片

### 组件结构
- 商品图：宽度 100%，高度 120px
- 商品名：字号 14px，最多2行
- 价格：字号 16px，颜色 #f5222d
- 加入购物车按钮：宽度 100%，高度 32px
```

## 与其他 skill 的配合

### 完整工作流程

```bash
# 1. 高层决策
/think-tank 我想做一个生鲜电商平台

# 2. 产品经理编写 PRD
/product-manager 基于 think-tank 的评审报告，编写 PRD

# 3. UI 设计师设计界面
/ui-designer 基于 PRD，设计生鲜电商平台的 UI

# 4. 开发实现
/omo 基于 PRD 和 UI 设计图，实现生鲜电商平台
```

## 最佳实践

1. **基于 PRD**：UI 设计必须基于 PRD，不能偏离功能需求
2. **遵循规范**：严格遵循设计规范，确保视觉一致性
3. **考虑可行性**：设计方案必须考虑技术可行性
4. **提交评审**：产出后提交设计评审，征求反馈
5. **持续优化**：根据反馈和用户数据，持续优化设计
