# Product Manager - 产品经理

产品经理是执行层角色，负责将高层决策（think-tank）转化为详细的产品需求文档（PRD）。

## 特性

- **规范化**：遵循统一的 PRD 模板和文档规范
- **结构化**：功能清单、用户故事、交互流程、验收标准
- **审核机制**：产出后提交给产品总监审核确认
- **可追溯**：所有 PRD 保存在 `.think-tank/prd/` 目录

## 安装

```bash
python3 install.py --module product-manager
```

## 快速开始

```bash
/product-manager 基于 think-tank 的评审报告，编写生鲜电商平台的 PRD
```

## 工作流程

```
think-tank（高层决策）
    ↓
product-manager（编写 PRD）
    ↓
产品总监审核
    ↓
PRD 正式生效
    ↓
ui-designer / 开发团队
```

## PRD 包含内容

1. **需求背景**：为什么做这个产品/功能
2. **目标用户**：用户画像和使用场景
3. **功能清单**：所有功能列表（含优先级）
4. **用户故事**：As a [角色], I want [功能], So that [价值]
5. **交互流程**：详细的用户操作流程
6. **验收标准**：功能完整性、交互体验、异常处理、性能、安全
7. **非功能需求**：性能、安全、兼容性
8. **里程碑**：开发计划和时间节点

## 使用示例

### 示例 1：基于 think-tank 编写 PRD

```bash
/product-manager 基于 think-tank 的评审报告，编写生鲜电商平台的 PRD
```

产品经理会：
1. 读取 think-tank 的评审报告
2. 理解决策和方向
3. 编写详细的 PRD
4. 提交给产品总监审核

### 示例 2：编写新功能 PRD

```bash
/product-manager 编写"会员制"功能的 PRD
```

产品经理会：
1. 分析会员制的需求
2. 设计会员等级、权益、充值方案
3. 编写详细的 PRD
4. 提交审核

## PRD 规范

### 功能清单格式

| 功能ID | 功能名称 | 功能描述 | 优先级 | 依赖 |
|--------|---------|---------|--------|------|
| F001 | 用户注册 | 用户通过手机号注册账号 | P0 | 无 |
| F002 | 用户登录 | 用户通过手机号+验证码登录 | P0 | F001 |

### 用户故事格式

```
**用户故事 US001：用户注册**
- As a 新用户
- I want 通过手机号注册账号
- So that 我可以使用平台购买商品

**验收标准**：
- [ ] 输入手机号，点击"获取验证码"
- [ ] 收到验证码短信（60秒内）
- [ ] 输入验证码，点击"注册"
- [ ] 注册成功，自动登录
```

### 交互流程格式

```
**流程：用户下单**

1. 用户进入首页
   - 显示商品分类
   - 显示推荐商品

2. 用户选择商品
   - 点击商品，进入详情页
   - 查看价格、库存、描述
   - 点击"加入购物车"

...
```

## 文档规范

首次使用时，产品经理会自动创建 PRD 模板（`.think-tank/prd-template.md`），包含：
- 文档结构
- 各章节说明
- 格式规范
- 示例

后续所有 PRD 都遵循此模板。

## 审核机制

产品经理产出 PRD 后，会自动提交给产品总监审核：
1. 功能清单是否完整？
2. 用户故事是否清晰？
3. 交互流程是否合理？
4. 验收标准是否明确？
5. 是否有遗漏或偏差？

产品总监审核通过后，PRD 正式生效。

## PRD 存储

所有 PRD 保存在 `.think-tank/prd/` 目录：
- `.think-tank/prd/生鲜电商平台-2026-01-22.md`
- `.think-tank/prd/会员制功能-2026-01-23.md`

便于追溯和版本管理。

## 与其他 skill 的配合

### 与 think-tank 配合

```bash
# 1. 高层决策
/think-tank 我想做一个生鲜电商平台

# 2. 产品经理编写 PRD
/product-manager 基于 think-tank 的评审报告，编写 PRD

# 3. UI 设计师设计界面
/ui-designer 基于 PRD，设计生鲜电商平台的 UI

# 4. 开发实现
/omo 基于 PRD 和 UI 设计图，实现生鲜电商平台
```

## 最佳实践

1. **基于决策**：PRD 必须基于 think-tank 的决策，不能偏离方向
2. **遵循规范**：严格遵循 PRD 模板和文档规范
3. **完整详细**：功能清单、用户故事、验收标准缺一不可
4. **提交审核**：产出后必须提交给产品总监审核
5. **持续更新**：根据反馈和变化，及时更新 PRD
